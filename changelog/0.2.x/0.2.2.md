# 0.2.2 — 2026-09-21

## Added

- **Claude Code plugin prompts for `SHODAN_API_KEY` / `CERTSPOTTER_API_KEY`** via `userConfig`; the Codex plugin forwards them through `env_vars` instead of an unresolved literal `${VAR}`.
- **CodeQL workflow** (`.github/workflows/codeql.yml`) — the one GitHub Actions file this project carries; requires the repo's CodeQL default setup to stay off.

## Changed

- **HTTP sessions default to `stateless`** via `createApp({ sessionMode: 'stateless' })`; an explicit `MCP_SESSION_MODE` still overrides it, and stdio is unaffected ([#11](https://github.com/cyanheads/attack-surface-mcp-server/issues/11)).
- **`no_data` (`attacksurface_lookup_host`) and `no_surface` (`attacksurface_map_domain`)** now log at `notice`, not `error` — both are ordinary answers; wire output is unchanged.
- **Skills tree moved to `framework-skills/`** so a plugin install no longer loads the development skills; README restructured into an Overview + capability reference; issue forms allow blank issues and link private security-advisory reporting.
- **`@cyanheads/mcp-ts-core` ^0.12.3 → ^0.13.6**: argument rejections carry `structuredContent.error` (`-32602`) with `reason: invalid_arguments` and a `Recovery:` hint listing accepted keys ([cyanheads/mcp-ts-core#377](https://github.com/cyanheads/mcp-ts-core/issues/377), [cyanheads/mcp-ts-core#445](https://github.com/cyanheads/mcp-ts-core/issues/445)).
- **A misspelled snake_case/camelCase argument key now resolves to the declared key** (e.g. `timeout_ms` → `timeoutMs`) instead of being rejected ([cyanheads/mcp-ts-core#452](https://github.com/cyanheads/mcp-ts-core/issues/452)).
- **Tool error text ends with `(reason <reason>)`**, adding `· retryable` / `· not retryable` when declared ([cyanheads/mcp-ts-core#458](https://github.com/cyanheads/mcp-ts-core/issues/458)).
- **Upstream HTTP 500s from Shodan, crt.sh, or Certspotter now retry** like the rest of the 5xx range ([cyanheads/mcp-ts-core#323](https://github.com/cyanheads/mcp-ts-core/issues/323)).
- **An empty or unsubstituted `${…}` value for one of this server's own env vars reads as unset** rather than failing startup ([cyanheads/mcp-ts-core#427](https://github.com/cyanheads/mcp-ts-core/issues/427)).
- **`/.well-known/mcp.json` publishes the resolved session mode** under `_meta["io.github.cyanheads.mcp-ts-core/sessionMode"]` ([cyanheads/mcp-ts-core#387](https://github.com/cyanheads/mcp-ts-core/issues/387)).
- **`SIGTERM`/`SIGINT` end the process explicitly** once shutdown settles ([cyanheads/mcp-ts-core#435](https://github.com/cyanheads/mcp-ts-core/issues/435)).
- **Six tools' `outputSchema`** render nullable string fields as `type: ["string", "null"]` instead of `anyOf` (from the zod 4.4.3 → 4.6.5 bump, not the framework).

## Fixed

- **`resolveSafeHost` pins a dual-stack host to IPv4.** The TLS handshake (`attacksurface_inspect_tls`, `map_domain`'s TLS posture) and the WHOIS port-43 fallback previously dialed the resolver's first address, which under Bun is the AAAA record — so a network without an IPv6 route, Docker's default bridge included, failed to connect ([#14](https://github.com/cyanheads/attack-surface-mcp-server/issues/14)).
