# 0.2.3 — 2026-09-30

## Changed

- **`@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.10.** Error envelopes carry `data.requestId` and no longer carry server stack traces or request context; a declared `recovery` hint is filled whenever a failure names its `reason`.
- **MCP SDK 2.1.0 transport rules** arrive with the framework: a 2026-07-28 POST without `MCP-Protocol-Version` is refused `400`, as is a JSON-RPC batch over 100 messages.
- **The container image installs production dependencies in a `$BUILDPLATFORM` stage** that cross-installs for the target architecture; `scripts/install-otel.ts` adds the OpenTelemetry packages at the framework's peer ranges. Base images move `oven/bun:1.4.0` → `1.4.2`, and the unread `MCP_FORCE_CONSOLE_LOGGING` env is gone.
- **`attacksurface_lookup_host` descriptions** no longer call the host lookup free, and say a search may consume Shodan query credits.
- **`attacksurface_resolve_dns` and `attacksurface_inspect_tls` descriptions** state what the code returns: `records` comes from the first configured resolver, and `certificate` is the leaf, with `chainDepth` beside it.
- **Packaging and tooling:** npm `files` excludes `dist/*.mcpb`; `.mcpbignore` excludes `docs/idea.md` and `logs/`; `manifest.json` `author` is name-only; `packageManager` moves to `bun@1.4.2`; 31 framework skills and the `devcheck`, `lint:mcp`, `lint:packaging`, `release:github`, and skill-version scripts are re-synced; README capability entries are condensed.

## Fixed

- **`attacksurface_resolve_dns` reports `SERVFAIL` as a resolver failure** ([#3](https://github.com/cyanheads/attack-surface-mcp-server/issues/3)). `ESERVFAIL` was read as an absent record and left `queryError` and `hostError` null; its message now fills both, alongside any records that did resolve.
- **`attacksurface_probe_http` reports redirect exhaustion as a transport error** ([#4](https://github.com/cyanheads/attack-surface-mcp-server/issues/4)). A redirect past the ten-hop limit was returned as the final response with `transportError: null`; it now returns `finalStatus: 0` and `transportError: "Exceeded 10 redirects without a final response."`.
- **`attacksurface_inspect_tls` returns `daysUntilExpiry: null` for an unparseable not-after date** ([#5](https://github.com/cyanheads/attack-surface-mcp-server/issues/5)) instead of `NaN`, which failed the output schema. Each unparseable bound adds a finding, and the field's schema is now `number | null`.
- **`attacksurface_lookup_host` rejects blank and non-IP host-mode targets before contacting Shodan** ([#6](https://github.com/cyanheads/attack-surface-mcp-server/issues/6)). A blank or whitespace-only `target` fails input validation in either mode; a host-mode hostname, URL, CIDR, `host:port`, or bracketed IPv6 address returns the new `invalid_target` error.
- **`attacksurface_probe_http` no longer infers a WAF from a `Server` banner** ([#2](https://github.com/cyanheads/attack-surface-mcp-server/issues/2)). `server: cloudflare` yields one `Cloudflare` detection in category `cdn` and `server: awselb` one `AWS ELB` in `other`; each previously produced a `server` entry plus a `waf` entry.

## Security

- **`attacksurface_inspect_tls` on an IP-literal host could end the server process** ([#16](https://github.com/cyanheads/attack-surface-mcp-server/issues/16)). `tls.connect` rejects an IP address as the TLS ServerName synchronously, and the handshake timer scheduled before it later fired against an uninitialized socket. Literal IPv4/IPv6 hosts now omit SNI, and the timer is created only after `tls.connect` returns, so a synchronous connect failure stays a per-host `handshakeError`.
