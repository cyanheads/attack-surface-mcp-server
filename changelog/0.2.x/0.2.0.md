# 0.2.0 — 2026-08-21

0.1.2 renamed the per-target `error` output field on four tools but shipped as a patch release flagged `breaking: false`. It was not: the old field name is absent from the new output, so any client reading `result.error` (or a nested per-item `error`) now reads `undefined` and silently treats a failed probe as a clean one. This release ships no source change — it corrects the version and changelog record for that break. Consumers who pinned `^0.1.1` or earlier and have not adopted the 0.1.2 field names should treat 0.2.0, not 0.1.2, as their upgrade point.

## Changed

- **Migration floor corrected for the 0.1.2 field renames** — no code change; see the table below and update any client still reading the old field names.

| Tool | Field path | Old name | New name |
|---|---|---|---|
| `attacksurface_enumerate_subdomains` | `sourceStatuses[].error` | `error` | `sourceError` |
| `attacksurface_inspect_tls` | `results[].error` | `error` | `handshakeError` |
| `attacksurface_probe_http` | `error` | `error` | `transportError` |
| `attacksurface_resolve_dns` | `results[].error` | `error` | `hostError` |
| `attacksurface_resolve_dns` | `results[].resolverResults[].error` | `error` | `queryError` |
| `attacksurface_resolve_dns` | `results[].reverse[].error` | `error` | `lookupError` |

No other tool, resource, input schema, or error contract changed between 0.1.1 and 0.1.2 — these six field paths (four tool files) are the full scope of the break.
